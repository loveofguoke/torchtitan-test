# GLM-5 性能优化实验与面试速查

本文把候选实现、实验命令、指标和面试需要说明的原理放在一处。正式性能结论仍以
`README.md` 的 Ascend Profiler 流程和生成报告为准。

## 1. 实验原则

性能实验必须固定模型、checkpoint、token plan、topology、precision、batch、sequence
length、warmup 和测量窗口。一次只改变一个主要因素。先用 profiler-off 重复运行看
稳态吞吐，再用短 profiler window 解释原因，最后跑正式 precision。

Full DSA、kernel、graph、parallelism、recompute 和 profiler 都是正交因子；不选时不
改变普通训练。不要在一次归因实验里同时打开多个新优化。

## 2. 已有 profile

| Profile | 维度 | 实际变化 | 重点指标 |
|---|---|---|---|
| `reference` | baseline | PyTorch Full DSA | step time、kernel inventory |
| `triton-full-dsa` | 计算 | Triton-Ascend index score + SparseMLA forward/backward | AICore time、launch、intermediate |
| `sparse-mla` | 计算/内存 | Ascend 原生 sparse attention | output/grad、kernel time |
| `async-tp` | 通信 | compile + async TP | exposed HCCL、critical path |
| `foreach-optimizer` | runtime | 批量 optimizer tensor op | launch/CPU time |
| `chunked-loss` | 内存 | 16 个 loss chunk | peak memory、LM-head launch |
| `cpu-offload` | 内存/copy | FSDP CPU offload | device memory、H2D/D2H |
| `full-recompute` | 计算换内存 | full-block AC | saved memory、backward cost |

## 5. 如何解释四类优化

### 计算融合

融合的价值不是“kernel 数量越少越好”，而是减少 global-memory round trip、launch 和
重复读写。Triton indexer 把 dot、ReLU、head-weight reduction、mask 融合，并避免
`[N,Q,K]`；SparseMLA kernel 依据 top-k index 按需加载 KV，不构造 dense attention。

### 通信重叠

同步路径是 `collective -> wait -> GEMM`；重叠路径是 `issue collective -> independent
GEMM -> wait at first consumer`。判断依据是 collective 在 critical path 上的暴露时间
和 step time，不是通信总时间或 overlap 百分比。

### 内存调度

active memory 是当前 tensor 真正占用，reserved memory 是 allocator 持有。workspace
可减少反复申请，但可能增加 retained memory；chunking 降低峰值，却增加 launch；
offload 降低 device memory，却增加传输和 host 压力。

### 重计算

activation checkpoint 不保存一部分 forward activation，backward 时重跑 forward。
节省显存但增加计算/通信。对 DSA/MoE，top-k 是离散控制流，selective policy 应保存
top-k，避免重算时边界翻转。

## 6. Lightning Indexer 和 SparseMLA

Lightning Indexer 是“便宜的全局检索器”，不是正式 attention。TorchTitan 中：

```text
Glm5DsaIndexer -> projection/RoPE/norm/head weight
DSAIndexerTopK -> global score/mask/top-k
```

SparseMLA 是 `Glm5Attention.inner_attention`，只对 indexer 选中的 compressed KV 做正式
attention。它不是 dense attention 的 subclass，而是一个稳定可替换的 component。

TP 把 query head 分片并让 SparseMLA 在本地执行；EP 只影响 MoE，因此 TP+EP 的
attention 接口兼容。CP correctness path 先收集全局 KV。PP 因跨 stage index carrier
尚未实现而从 Full DSA `all` 排除。

## 7. 从主流框架迁移优化时检查什么

可以借鉴 Megatron-Core/TorchTitan 的 TP overlap、grouped GEMM、fused SwiGLU、
selective recompute、distributed optimizer 和 EP pipeline，但不能直接复制调用方式。
每项迁移必须检查：

1. 数学公式、dtype 和累加顺序；
2. shape/layout/stride；
3. parameter 与 state-dict 兼容；
4. TP/EP/CP placement 和 gradient placement；
5. autograd、graph capture、dynamic shape；
6. profiler 中是否真的改善端到端 critical path。

## 8. 报告判读

候选至少同时满足：operator probe 通过、smoke/backward 完成、正式 loss/grad-norm
接受、没有新 graph break/AICPU fallback、且声明的性能机制出现在 trace 中。只在
microbenchmark 变快的实现仍然是 operator prototype，不能称为训练优化。

## 9. 主流框架对照与资料

- TorchTitan：
  `torchtitan/distributed/fsdp.py::apply_fsdp_to_decoder` 是 FSDP 粒度边界，
  `distributed/spmd_types.py::spmd_redistribute_per_axis` 是多轴 placement transition，
  `experiments/graph_trainer/ep_eager_chunk.py::maybe_apply_ep_overlap_eager_chunking` 和
  `ep_overlap_pass.py::ep_overlap_schedule_pass` 是 eager/graph EP overlap 对照，
  `distributed/activation_checkpoint.py::FullAC`、`SelectiveAC`、`MemoryBudgetAC` 是重计算边界。
- Megatron-Core：
  `megatron/core/distributed/fsdp/src/megatron_fsdp/param_and_grad_buffer.py::ParamAndGradBuffer`
  对应连续 bucket，`transformer/moe/token_dispatcher.py::MoEAlltoAllTokenDispatcher` 和
  `moe_utils.py::permute`/`unpermute` 对应 EP 数据流，
  `pipeline_parallel/schedules.py::forward_backward_pipelining_without_interleaving` 对应 1F1B，
  `core/recompute.py::checkpointed_forward` 对应重计算。
- DeepSpeed：
  `deepspeed/runtime/zero/stage3.py::IPGBucketZ3`、
  `runtime/zero/stage_1_and_2.py::IPGBucket` 对应 ZeRO bucket/overlap，
  `runtime/utils.py::partition_balanced` 对应 PP 静态均衡，
  `runtime/activation_checkpointing/checkpointing.py::partition_activations` 和 `checkpoint`
  对应 activation partition/recompute。它们用于解释边界，不能直接替换 TorchTitan 的
  FSDP state/optimizer contract。
- vLLM：`vllm/v1/core/block_pool.py::BlockPool.get_new_blocks`、`touch`、`free_blocks`
  和 `v1/core/kv_cache_manager.py::allocate_slots` 是 paged KV/prefix cache 对照；当前训练
  没有 KV cache，不能把推理收益套到训练 step time。
- GLM Full DSA 工程参考：
  `slime_plugins/models/glm5/ops/indexer.py::lighting_indexer`、`IndexerFunction`，
  `ops/sparse_mla.py::SparseMLA`，以及 `glm5.py::source_compute_layer` 和其局部
  `fused_select_topk`。TorchTitan/Turbo 不导入这些符号，只对照数学和工程边界。
- Triton/Triton-Ascend：实现本地融合 kernel；collective 仍由 NCCL/HCCL 和分布式层
  调度。

所有本地参考都用“模块路径 + 符号”定位，不使用容易被上游更新推移的行号。真实八卡
